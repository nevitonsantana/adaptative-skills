Use these profiles when the catalog summary is not enough to decide how a skill works, what it returns, or how to verify the result.

Each profile is generated from its canonical `skills/<name>/SKILL.md` file. The public page adds orientation and navigation, but it does not replace or independently rewrite the contract.

## Pilot profiles

| Skill | Category | Use it when |
|---|---|---|
| [`documentation`](https://nevitonsantana.github.io/adaptive-skills/skills/documentation/) | Documentation | Creating, restructuring, or auditing onboarding, manuals, guides, and technical documentation |
| [`feature-planning`](https://nevitonsantana.github.io/adaptive-skills/skills/feature-planning/) | Engineering | Turning a feature request into staged delivery |
| [`ux-strategy`](https://nevitonsantana.github.io/adaptive-skills/skills/ux-strategy/) | Design | The interaction direction is still open |

This first set validates the public profile format across three categories. The remaining generic skills continue to appear in the [complete skills catalog](https://nevitonsantana.github.io/adaptive-skills/getting-started/skill-catalog/).

## What each profile includes

- the canonical description, category, version, and owner
- direct navigation to usage, restrictions, core moves, outputs, and verification
- the complete skill contract
- an explicit link to the source file

Public profiles are a reader-facing projection. They do not change skill behavior, routing authority, or runtime execution.
